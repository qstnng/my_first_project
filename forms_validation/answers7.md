Ответы на вопросы по вёрстке и валидации форм

1. Какие HTML5-атрибуты используются для клиентской валидации?

required — поле обязательно. minlength / maxlength — минимальная и максимальная длина. min / max — диапазон для чисел и дат. pattern — регулярное выражение для проверки. type (email, tel, url, number, date) — задаёт тип данных и автоматическую проверку. step — шаг для числовых полей. Атрибуты работают без JavaScript, браузер сам проверяет значения.

2. В чём разница между novalidate и отключением валидации через JS?

novalidate — HTML-атрибут формы, полностью отключает встроенную браузерную валидацию при отправке. Валидация в JS — выборочное управление: можно оставить часть проверок, добавить свои, отключить отдельные поля. В работе novalidate стоит на форме, а вся валидация выполняется вручную через JS, чтобы полностью контролировать сообщения об ошибках.

3. Как правильно связать label с полем ввода?

Два способа. Первый: <label for="email">Email</label> и <input id="email">. Второй: обернуть input внутрь label. Связь важна для доступности: скринридеры читают подпись при фокусе на поле, а клик по подписи переводит фокус в поле. Без связи пользователи скринридеров не понимают, что вводить.

4. Какие типы полей input подходят для разных данных?

text — имя, фамилия, общие текстовые данные. email — email-адрес с проверкой формата. tel — телефон, обычно вместе с pattern. password — пароль, символы скрыты. date — дата через календарь. number — числа с ограничениями. url — ссылки. checkbox — множественный выбор. radio — выбор одного из нескольких. select — выпадающий список.

5. Как работает валидация с pattern?

pattern принимает регулярное выражение. Значение поля проверяется на соответствие. Пример: pattern="\+7\s?\(\d{3}\)\s?\d{3}-\d{2}-\d{2}" проверяет формат +7 (999) 999-99-99. Используется для телефонов, почтовых индексов, номеров карт, паролей с требованиями. При несоответствии браузер показывает стандартное сообщение или можно переопределить через JS.

6. Какие события JavaScript используются для валидации в реальном времени?

input — срабатывает при каждом изменении значения, подходит для очистки ошибок. blur — при потере фокуса, используется для проверки после завершения ввода. change — при изменении значения (для select, checkbox). submit — при отправке формы. В работе: blur — для основной валидации, input — для очистки ошибок и проверки совпадения пароля.

7. Как обеспечить доступность сообщений об ошибках?

Использовать aria-describedby — связать поле с блоком ошибки. aria-invalid="true" — указать, что поле невалидно. aria-live="polite" на контейнере ошибок — скринридер озвучит новое сообщение. Тексты ошибок должны быть конкретными: не «ошибка», а «введите корректный email». Цвет не единственный индикатор — добавлять иконку или текст.

8. В чём преимущества fieldset и legend?

fieldset группирует связанные поля. legend задаёт заголовок группы. Скринридеры озвучивают legend при переходе к полям внутри группы. Помогает визуально разделить длинные формы на логические блоки — «Личная информация», «Безопасность». Улучшает и доступность, и восприятие.

9. Как реализовать кастомную валидацию для подтверждения пароля?

Обработать событие input на обоих полях. Сравнивать значения. При несовпадении — добавлять класс error и текст в span с id confirmPasswordError. При совпадении — очищать ошибку. В работе: validatePasswordMatch() вызывается при вводе в password и confirmPassword, а также при submit формы.

10. Какие CSS-методы используются для отображения валидности?

Псевдоклассы :valid и :invalid — автоматически применяются браузером к полям с атрибутами валидации. :focus, :not(:placeholder-shown) — уточняют состояние, чтобы ошибка не появлялась раньше времени. Классы .error через JS — для ручной валидации. :checked для radio и checkbox — отображение выбранного состояния. Анимация @keyframes shake — визуальное привлечение внимания к ошибке.
