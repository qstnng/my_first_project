Ответы на вопросы по базовым алгоритмам JS

1. В чем разница между временной сложностью O(n) и O(n²)?

O(n) — линейная сложность, время выполнения растёт пропорционально размеру входных данных. Пример: findMax (один проход по массиву), countVowels (один проход по строке). O(n²) — квадратичная, время растёт как квадрат размера. Пример: bubbleSort (два вложенных цикла). При 1000 элементов O(n) выполнит 1000 операций, O(n²) — миллион.

2. Как работает бинарный поиск и почему сложность O(log n)?

Бинарный поиск работает только на отсортированном массиве. На каждом шаге массив делится пополам: сравниваем искомый элемент с центральным, отбрасываем ту половину, где его точно нет. Количество шагов — это количество делений массива пополам, пока не останется один элемент. Для массива из n элементов это log₂(n) шагов. Отсюда O(log n).

3. Преимущества и недостатки пузырьковой сортировки?

Преимущества: простой алгоритм, легко реализуется, не требует дополнительной памяти (in-place), стабильная сортировка. Недостатки: медленная, O(n²) в среднем и худшем случае, неэффективна для больших массивов. На практике используется редко — только для обучения.

4. Как оптимизировать проверку на простое число?

Базовый перебор делителей до n. Оптимизация: перебирать только до √n, так как если у числа есть делитель больше √n, то есть и парный делитель меньше √n. Дополнительно: пропускать чётные числа после проверки на 2, использовать шаг 6 (проверять числа вида 6k ± 1). Для очень больших чисел — вероятностные тесты (Миллера — Рабина).

5. Разница между рекурсивной и итеративной реализацией Фибоначчи?

Рекурсивная: function fib(n) { return n < 2 ? n : fib(n-1) + fib(n-2); } — читается красиво, но имеет экспоненциальную сложность O(2^n) без мемоизации. Итеративная: цикл от 2 до n, хранит два предыдущих значения, сложность O(n). В работе использована итеративная версия как эффективная.

6. Какие методы отладки использовались?

console.log для вывода промежуточных значений. console.table для массивов. Инструменты разработчика (F12 → Console) для просмотра ошибок. Пошаговое выполнение через breakpoints в Sources. Тесты (runTest) для автоматической проверки результатов. Проверка крайних случаев: пустые массивы, нули, отрицательные числа.

7. Как работает алгоритм Евклида и почему он эффективен?

НОД(a, b) = НОД(b, a mod b). Алгоритм: пока b ≠ 0, заменяем пару (a, b) на (b, a mod b). Когда b = 0, ответ — a. Эффективен, потому что остаток от деления уменьшается на каждом шаге как минимум вдвое. Количество шагов — O(log(min(a, b))). Не требует дополнительной памяти.

8. Какие edge cases учитывать при работе с массивами?

Пустой массив (arr.length === 0). Массив из одного элемента. Отрицательные числа. Повторяющиеся элементы. Массив с одинаковыми значениями. Уже отсортированный массив. Массив, отсортированный в обратном порядке. Для binarySearch — массив должен быть отсортирован, иначе поведение неопределено.

9. Как улучшить удаление дубликатов для больших массивов?

Использовать Set: [...new Set(arr)] — сложность O(n), так как Set хранит уникальные значения в хеш-таблице. Без Set: сортировка + проход с проверкой arr[i] !== arr[i-1] — O(n log n). Или объект/Map для подсчёта вхождений — O(n), но занимает больше памяти. В работе использован Set как самый простой и быстрый вариант.

10. Какие принципы чистого кода применены?

Понятные имена функций (isPrime, findMax) и переменных (result, longest). Один уровень абстракции в функции. Комментарии со сложностью алгоритма. Разделение кода по файлам: логика в algorithms.js, тесты в tests.js. Обработка крайних случаев в начале функции (if (number <= 1) return false). Отсутствие дублирования кода. Возврат значения в одной точке.
