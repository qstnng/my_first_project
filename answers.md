"# Ответы на вопросы для самоконтроля" 

Вопрос 1. Какие три основные области работы с файлами в Git (рабочая папка, индекс, репозиторий) и чем они отличаются?

Рабочая папка — директория для редактирования файлов. Индекс — промежуточная область, куда файлы попадают после git add. Репозиторий — хранилище закоммиченных версий. Отличие: рабочая папка содержит текущее состояние, индекс — подготовленные к коммиту изменения, репозиторий — сохранённую историю.

Вопрос 2. Что происходит при выполнении команд: git add, git commit, git push?

git add — добавление изменений в индекс (подготовка к коммиту). git commit — сохранение изменений из индекса в локальный репозиторий. git push — отправка локальных коммитов в удалённый репозиторий (GitHub).

Вопрос 3. Почему важно писать информативные сообщения к коммитам, а не просто "исправление" или "update"?

Информативные сообщения позволяют понимать историю проекта, быстро находить нужные изменения и работать в команде. Сообщения типа "update" не несут полезной информации — по ним невозможно понять, что именно менялось.

Вопрос 4. Чем отличается git add имя_файла от git add .? В каких случаях лучше использовать каждый вариант?

git add имя_файла добавляет только указанный файл — применяется, когда нужно закоммитить часть изменений. git add . добавляет все изменения в текущей директории — применяется, когда все правки логически связаны и должны войти в один коммит.

Вопрос 5. Что показывает команда git status и как меняется её вывод на разных этапах работы?

Команда отображает состояние рабочей папки и индекса: изменённые файлы, файлы в индексе, неотслеживаемые файлы. Вывод меняется: до git add файлы имеют статус "untracked", после — "Changes to be committed", после коммита — "working tree clean".

Вопрос 6. Для чего нужна команда git remote add origin URL и что означает слово "origin"?

Команда связывает локальный репозиторий с удалённым. "origin" — стандартный псевдоним для основного удалённого репозитория. Допускается использование другого имени, но origin применяется по умолчанию.

Вопрос 7. Зачем нужен флаг -u в команде git push -u origin main при первой отправке изменений?

Флаг -u (--set-upstream) связывает локальную ветку с удалённой. После первой отправки возможно использование команд git push и git pull без указания репозитория и ветки.

Вопрос 8. Что такое ветка (branch) по умолчанию и какая у вас создалась (main или master)? Почему это важно?

Ветка по умолчанию — ветка, создаваемая при git init. В данном случае создалась ветка master (или main — зависит от версии Git). Это важно, поскольку GitHub использует main, и при расхождении имён возникает ошибка при push. Для исправления применяется команда git branch -M main.

Вопрос 9. Как просмотреть историю коммитов и какую информацию о каждом коммите вы видите?

Команда git log. Отображает хеш коммита, автора, дату и сообщение. Для краткого формата применяется git log --oneline — вывод хеша и сообщения в одну строку.

Вопрос 10. Что произойдет, если сделать изменения в файле, но не выполнить git add перед git commit?

Изменения не попадут в коммит. Git закоммитит только содержимое индекса. Изменённый файл останется в рабочей папке со статусом "not staged". Для включения изменений в коммит требуется сначала выполнить git add, затем git commit.
